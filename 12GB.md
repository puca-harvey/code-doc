# Hardware profile: 12 GB VRAM

Reference card: **NVIDIA GeForce RTX 5070** (12227 MiB total, as reported by `nvidia-smi`). Every number on this
page was measured on that card.

The general setup — installing Ollama, Continue and Cline, and the keybindings — lives in
[`README.md`](README.md). This file only covers what depends on how much VRAM you have.

## Why VRAM is the deciding factor

Ollama keeps a loaded model in VRAM. If the weights plus the KV cache do not fit, the model is split across VRAM
and system RAM, and tab completion becomes slow enough to be unusable. So the question that matters is not "which
card" but "does the biggest model fit".

| Model | Size on disk | Fits in 12 GB? | Fits in 8 GB? |
| --- | --- | --- | --- |
| `qwen2.5-coder:32b` | ~20 GB | No | No |
| `qwen2.5-coder:14b` | 9.0 GB | Yes | **No** — exceeds it before any context |
| `qwen2.5-coder:7b` | 4.7 GB | Yes | Yes |
| `granite4.2:8b` | 5.3 GB | Yes | Yes, alone |
| `llama3.1:8b` | 4.9 GB | Yes | Yes, alone |
| `nomic-embed-text-v2-moe:latest` | 957 MB | Yes | Yes |

## Model set

This is what [`continue/config.yaml`](continue/config.yaml) configures, and it is reproduced here so the reason for
each choice is on the record:

```powershell
ollama pull qwen2.5-coder:14b              # ~9 GB - autocomplete, and the model Cline edits with
ollama pull granite4.2:8b                  # ~5 GB - fast chat
ollama pull llama3.1:8b                    # ~5 GB - fallback chat
ollama pull nomic-embed-text-v2-moe:latest # ~1 GB - embeddings / semantic search
ollama list                                # verify
```

Budget **~20 GB of disk** for all four.

`qwen2.5-coder:14b` is the one model that holds the `autocomplete` role, because Ollama ships it with a native
fill-in-the-middle template:

```text
{{- if .Suffix }}<|fim_prefix|>{{ .Prompt }}<|fim_suffix|>{{ .Suffix }}<|fim_middle|>
```

It also advertises the `insert` capability, so Continue uses the real FIM code path — the model receives
*prefix + suffix* and returns only the middle. `granite4.2:8b` and `llama3.1:8b` have a bare `{{ .Prompt }}`
template with no `.Suffix`, so Continue falls back to pasting a raw `<|fim_prefix|>…<|fim_middle|>` prompt and the
model continues *past* the insertion point into unrelated prose. Fine for chat, bad for tab completion.

## Context length

`config.yaml` pins `contextLength: 8192` per model. With that, the ~9 GB model stays fully resident on a 12 GB card.
A machine-wide `OLLAMA_CONTEXT_LENGTH` would be requested *instead* and can push the model into CPU offload:

```powershell
# check whether one is set (empty output = not set)
[Environment]::GetEnvironmentVariable("OLLAMA_CONTEXT_LENGTH", "User")

# remove it - config.yaml sets contextLength per model instead
[Environment]::SetEnvironmentVariable("OLLAMA_CONTEXT_LENGTH", $null, "User")
```

Re-check this after any Ollama tinkering.

## Verify

```powershell
ollama ps     # after a request: the model should be listed as 100% GPU
```

`ollama ps` lists only *loaded* models, so an empty result just means nothing has been requested yet. Type a few
lines in a `.py`/`.ts` file and press `Tab` — Continue should complete it inline.

## Measured throughput

Numbers from this machine, for comparison against your own:

| Model | Speed | Role here |
| --- | --- | --- |
| `granite4.2:8b` | ~105 tok/s | Chat, planning, explanation |
| `qwen2.5-coder:14b` | ~65 tok/s | Autocomplete, code edits |

Splitting the roles gets both: the 8 B model is markedly faster for prose, the 14 B is much better at code.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Completions feel sluggish | CPU offload | `ollama ps` — if not 100% GPU, lower `contextLength` or clear `OLLAMA_CONTEXT_LENGTH` |
| Ollama "not enough memory" | Model plus context exceeds VRAM | Close other GPU apps, or keep `contextLength: 8192` |
| Completion continues into prose | A non-FIM model holds the `autocomplete` role | Only `qwen2.5-coder:14b` supports FIM here; keep `autocomplete` off Granite/Llama |

## CPU-only machines

Everything still runs, but the 14B model will be slow for tab completion — expect seconds instead of milliseconds.
On a CPU-only box, `qwen2.5-coder:7b` is the more sensible `autocomplete` model.
